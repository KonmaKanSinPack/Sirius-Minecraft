## 2. 设计取舍

- **cancel 接线走构造期闭包**：`registry.execute(client, name, args)` 签名没有 loop 引用，故 `AgentLoop` 构造默认注册表时传 `cancel=lambda: self._stop_requested`（late-binding 读当前值）。`default_registry(cancel=None)` 向后兼容（独立使用/测试时原语不可取消）。显式传入 `registry=` 时不自动接 cancel——调用方自负责
- **Primitives 在 tools.py 里延迟导入**：primitives.py 顶部 `from .tools import ToolOutcome`，模块级反向 import 会成环；`_primitive_factories` 函数体内 import 消解。每次 handler 调用实例化一个 Primitives（无状态包装，client 按次传入——循环里传 LoopClient，command 走自回显登记）
- **屏障判定用 `screen_open` 而非类名清单**："loading/overlay/level 类名匹配"对模组自定义 screen 不可靠，按 spec 兜底口径"非 null screen 就等"。getGuiState 调用失败视同无屏放行（防丢命令的措施不该反过来卡行走）。屏障放在 `_walk_to`（非公开 `walk_to`），collect_block 的走位同受保护；等待中也查 cancel（急停 SLA 不因屏障破功）
- **屏障超时话术即教学**："界面被 X 占用（等待 10s 未消失），此时发命令会丢失；先用 getGuiState 查看并处理界面（必要时按 ESC 关闭），再重发 walkTo"——模型读文本可自救（Numen 手段）
- **滚动状态替换式注入**：固定前缀 `〔当前状态〕` 识别；每步先移除上一条再追加（历史恒至多一条，不累积）。摘要单行化：位置 + 生命/饥饿/氧气（getStats 现无朝向/主手字段，将来扩充各加一行即可）。getStats 失败跳过该步注入、旧状态留在原地，不阻塞循环。首步也注入（与初始观测轻微重复，换逻辑统一）
- **工具注册顺序**：三原语排在键鼠之后、command/finish 之前；选用顺序的权威是系统提示的分层引导，注册表只保证都在表里
- **collect 的 count 1..64 / block_ids 1..16**：16 与 bridge world.query filter 契约对齐；64 是单次任务合理上限（防一次调用挖穿整个矿脉预算）
