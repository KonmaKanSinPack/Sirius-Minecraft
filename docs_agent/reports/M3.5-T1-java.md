## 设计取舍（注释均已写入代码）

1. **过滤扫描扫全立方 + 容量 32 的有界最大堆**：扫描序是 x→y→z 不是距离序，在 32 命中处提前 break 会保留"空间角落"而非"最近"（恰是本扩展要修的问题）。堆满后新命中仅当严格更近才驱逐堆顶；**每个位置仍要 probe**（不 probe 无法区分"丢弃的是匹配"与"非匹配"，而 truncated 只能对丢弃的匹配为真），但每位置簿记 O(1)、响应规模有界。range=64 时全立方 129³≈2.1M 次 getBlockState 在主线程，实测感知留给 T5 真机观察；若慢，备选优化是球形裁剪或按 chunk 截断（记为未完成项）。
2. **距离基准 = 玩家精确坐标 vs 方块中心 (x+0.5,y+0.5,z+0.5)**（与 lookAt 瞄准点一致）；立方包围盒仍 = `floor(玩家坐标)±ceil(range)`，与 v1.0 未过滤扫描的块集合完全一致（角上块可达 r√3，历史语义，未收紧）。并列距离按 (x,y,z) 字典序打破，保证确定性。
3. **filter 校验规则**：字符集镜像 `ResourceLocation`（namespace `[a-z0-9_.-]`、path `[a-z0-9_./-]`，小写、至多一个冒号、`#` 前缀标记 tag）；缺 namespace 补 `minecraft:`（`#logs`→`#minecraft:logs`）。空数组 → -32602（缺省不过滤 = 完全省略 filter 或显式 null）。**entities + `#tag` → -32602**（spec 只定义了 registry-name 比较EntityType.getKey；拒绝优于静默空结果）。
4. **entities truncated 顺带修**：超 128 上限时 `truncated:true`（此前静默截尾）；序保持调用方（渲染列表）序，未加距离排序（spec 仅 blocks 要求最近优先）。
5. **hold 语义**：PRESS 仍由主线程任务内联注入（与 tap 完全同路径），仅 RELEASE 由 SCHEDULER 延迟 hold_ms；`count` 与 `hold_ms` 互斥判定基于 **count 是否显式出现**（`{"count":1,"hold_ms":600}` 也拒）——避免"默认值与显式值混淆"。`hold_ms:0` 合法（RELEASE 立即调度）。
6. **v1.0 路径零改动**：原 5 参 `scanBlocks`、原 burst 时序（R@25/P@50/R@75…）逐毫秒保留并有断言；`clickResult` 无 hold 时输出字段集合与旧版完全一致（新增字段仅在 hold 模式出现）。
