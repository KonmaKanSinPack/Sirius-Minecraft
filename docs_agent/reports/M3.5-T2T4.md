## 关键决策与理由

1. **`tool_result` 钩子而非覆写 `_on_request`**：基类的帧校验/能力检查/TOOL_PARAMS pydantic 校验流水线保持单一来源，FakeWorldBridge 只在"算结果"这一步换实现；scripted 剧本仍优先生效（"未覆盖回落 MockScript 行为"自然成立）。
2. **原语内部 `_StepResult(ok, text)`、公开面 `ToolOutcome`**：`collect_block` 需要知道子步骤（walk/dig）成败来决定收尾话术，但 `ToolOutcome` 只有 text——内层结构化、外层文本化，两头都干净。
3. **dig 存在性复核的查询半径 = `min(距离+1.5, 64)`**（不是 spec 草案里的固定 6）：固定 range=6 时目标在 6格外会查不到，被误报成"已不存在→直接成功"；半径盖住目标后，"看不到"只剩两种真语义——已空（≤64 格内）或远超感知（>64 格，教学先走位）。这是实现中发现并修掉的规格边角。
4. **FakeWorldBridge 的点击删除条件**：左键 + `hold_ms≥100` + 眼位→方块中心 ≤4.5 格 + 视线夹角 ≤30°；`minecraft:bedrock` 永不破坏（"挖不破"教学场景的现实对应物）。tap（无 hold_ms）挖不掉方块，与真客户端语义一致。
5. **看门狗/静默常量不进构造参数**：生产代码保持 spec 的模块级常量形态（取值理由写在头部注释），测试用 `monkeypatch.setattr(primitives, "WALK_STALL_SECONDS", 0.3)` 压短——不为测试放宽 API。
6. **`count`/`hold_ms` 互斥没做进 pydantic**：主管任务书只要求加字段；互斥校验是 Java 侧 `-32602` 的事（T1-Java），brain 侧原语从不多发 count。

## 实现要点 / API 笔记

- **协作式取消**：每个微步循环顶部查 `cancel()`（`poll_interval=0.5s` → 急停 ≤1s 生效）；walk 取消/超时都会发 `#stop`（经 `client.command` 的 T→text→ENTER 时序，本身 ~0.7s）；dig 取消不发任何停止帧（点击是 PRESS→RELEASE 原子对）。
- **walk 看门狗**：`dist < best-0.05` 才算有进展（吸浮点抖动）；15s 无进展重发一次 `#goto`（`resent` 标志保证只重发一次），之后继续等超时——与 Numen 近重试档一致。
- **collect 收尾三段话术**：`n≥count` 全收 / `0<n<count` 部分收（仍成功，注明"范围内已无更多"）/ `0` 教学失败（含 `#tag` 写法提示）；walk/dig 子步骤失败会 break 并把子建议织进收尾文案。
- **假 Baritone**：`#goto x [y] z` 两参/三参都收（两参保持当前 y，平地世界）；每 0.5s 推进 `move_speed×0.5` 格（4.3 m/s → 2.15 格/步），到位 snap；`move_speed=0` 即冻结世界（超时/看门狗测试用）。mover 任务经 `_track` 登记，`close()` 统一取消，不留悬挂协程。
- **wire 记录**：`server.submitted`（ENTER 提交的聊天行）、`server.looks`、`server.clicks`——测试断言 #goto/#stop/hold_ms 的真值不用抓包。
- **方块 filter 语义**（与 T1 Java 契约对齐）：条目为 registry 名（短名自动补 `minecraft:`）或 `#tag`（`#logs`/`#minecraft:logs` 等价）；内置 logs/planks 两张 tag 表。命中按与玩家距离平方升序，cap 32 + `truncated`。注意 range 是**立方每轴 ±ceil(range)**（Java scanBlocks 同口径），不是欧氏球。
- **MC 欧拉角**（fakeworld 的 lookAt/瞄准）：yaw 0=+Z 南、90=-X 西；pitch 正=低头。视线向量 `(-sin(yaw)cos(pitch), -sin(pitch), cos(yaw)cos(pitch))`。
